# 设计质量系统

## 解决什么问题

多数"不好看"不是审美问题，是系统缺失：间距随手写、字号自成一套、颜色没有层级、状态没做完。本规范把它们拆成可执行约束 + 可检查动作，让产出稳定落在"专业"区间，而不是靠灵感。

核心信条三条，按顺序执行：

1. **先约束，后创作** —— 没有刻度就没有一致性。
2. **先灰度，后上色** —— 颜色用来强调，不用来补层级。
3. **先结构，后细节** —— 圆角、阴影永远最后调。

## 开工前先问三个问题

| 问题 | 答案决定什么 |
|---|---|
| 这是**新建**还是**改造**？ | 改造必须先诊断，不能直接换配色 |
| 用户看它的**第一目的是什么**（读、点、比、买）？ | 决定唯一的主行动和视觉焦点 |
| **谁在什么设备上看**（手机、显示器、投影、打印）？ | 决定字号下限、信息密度、对比度要求 |

三个问题答不出来，就先问用户，不要猜。

## 模式与走法

| 模式 | 用户意图 | 走法 |
|---|---|---|
| 新建 | 从零做界面/页面/海报/PPT | 步骤 1 → 5，先立 token 再动手 |
| 改造 | 已有设计，说"不好看/帮我优化" | 步骤 0 诊断 → 定点修复 → 复评 |
| 评审 | 只要意见，不要改 | 步骤 0 + 评分卡，输出问题清单 |

**改造任务禁止跳过步骤 0 直接换配色。** 多数"丑"的根因在层次和间距。

## 输出要求

- **说具体值**：把"增加留白"改成"区块间距 24 → 48px，卡片内边距 16 → 24px"。
- **一次只改 1–3 个维度**，让用户能看出差别；不要一次推翻全部。
- **保留原有结构与信息**，除非结构本身是问题。
- **改完必须复评**：同一套标准再跑一遍，给出修改前后分数。

## 步骤 0：诊断

### 有 HTML/CSS

```sh
python3 scripts/audit_design.py <文件或目录>
```

输出 0–100 分、按维度扣分明细、硬伤清单。机器结论当线索，不当结论——它只覆盖约 40% 的可见问题。

### 无代码（截图 / PPT / 海报 / Figma）

四个测试，每个 10 秒：

| 测试 | 做法 | 失败说明 |
|---|---|---|
| 模糊测试 | 眯眼或缩到 20% 看 | 第一眼落在哪？如果视线无处落脚 → 层次失败 |
| 灰度测试 | 转灰度 | 层级塌陷 → 全靠颜色撑，层级没做 |
| 三秒测试 | 计时 3 秒 | 说不出"这是什么、该做什么" → 信息架构问题 |
| 边缘测试 | 看四边 | 内容贴边、无留白 → 版式没收窄 |

### 诊断输出固定三段

```
现状：__/10（或 __/100）
最痛 3 个问题：①… ②… ③…
修复顺序：结构（…）→ 视觉（…）→ 细节（…）
```

优先级永远 **结构 → 视觉 → 细节**。

### 症状 → 处方速查

用户的原话通常不是设计术语，按症状查：

| 用户说 | 真实问题 | 第一处方 |
|---|---|---|
| "很土 / 廉价" | 间距太挤、内容满宽、纯灰、阴影脏 | 间距升一档、容器收到 1280 内、中性色加色相 |
| "很乱 / 眼晕" | 没有层次、字号太多、所有元素同等重量 | 三级文字色、字号压到 5–7 种、次要信息降级 |
| "很空 / 没重点" | 均分布局、留白无节奏 | 做 1 主 + n 次，主元素放大 1.5 倍 |
| "像模板 / 像 AI 做的" | 居中一切、每块都圆角加阴影、紫蓝渐变 | 左对齐、去掉一半阴影、换单色强调 |
| "看着累" | 行长过宽、行高太紧、对比不足 | 收窄到 65ch、行高 1.65、正文提到 #111827 |
| "点不到 / 用着别扭" | 触控太小、状态缺失、错误不可恢复 | 44×44 热区、补 5 态、加撤销 |
| "不够高级" | 细节不一致、字重乱、圆角乱 | 统一 4 档圆角、字重只用 400/500/600/700 |

## 步骤 1：立约束（Token）

动手写样式前锁定五组值。**出现 13px、17px、22px 这类任意值，就是不协调的开始。**

| 类别 | 刻度 | 通过条件 |
|---|---|---|
| 间距 | 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96 | 所有 padding/margin/gap 都在刻度上 |
| 字号 | 12 / 14 / 16 / 18 / 20 / 24 / 30 / 36 / 48 / 60 | 一屏内 ≤ 7 种 |
| 行高 | 正文 1.5–1.75；标题 1.05–1.25；标签 1.3–1.4 | 每个文本元素都显式声明 |
| 圆角 | 4 / 8 / 12 / 16 | 同一界面 ≤ 3 档 |
| 阴影 | 4 级，双层（贴合 + 氛围） | 按层级用，不滥用 |

```sh
python3 scripts/make_tokens.py --seed "#2563eb" --mode both --out tokens.css
```

没有种子色时的默认取值：品牌 500 `#2563eb`、中性阶偏冷、背景 `#fafafb`、文字 `#111827`。

详见 [foundations.md](foundations.md)。

## 步骤 2：定版式与层次

**通过条件**：缩到 20% 仍能看出主次；转灰度层次不塌。

- **收窄内容宽度**：正文 45–75 字符（`65ch`），表单 320–480px，主容器 1080–1280px。满屏铺满是廉价感第一来源。
- **默认左对齐**。只有短标题、单一 CTA、空状态可居中。整页居中 = 没有版式。
- **层次三杠杆**：字号、字重、颜色。**不要三个一起拉满**——主标题"大+粗+深"，正文就只能是"常规+中灰"。
- **间距表达关系**：组内 ≤ 组间的一半。标题贴内容，远离上一组。
- **打破均分**：做"1 主 + n 次"，或用 2/3 + 1/3 的不对称栅格。
- **对齐轴 ≤ 2 条**。同屏混用居中、左对齐、右对齐，视线会走 Z 字。

数值与栅格见 [foundations.md](foundations.md) 第 5 节。

---

## 步骤 3：上色

**通过条件**：先摘掉颜色，版式依然成立。

- 颜色只承担三件事：**品牌识别、状态、强调**。不用来补层次。
- **视觉权重 60 / 30 / 10**：60% 中性底与留白、30% 次级信息、10% 强调色。强调色超过 10% 就不叫强调。
- **文字只用三级**：主 `#111827` / 次 `#4b5563` / 弱 `#9ca3af`（弱色仅限非关键信息，不得当正文）。
- **中性色带色相**：冷调偏蓝、暖调偏黄。纯灰显廉价。
- **暗色不是反色**：表面越高越亮，文字用 87% / 60% 不透明度的白，避免纯白大面积。
- 大面积不用纯 `#000` / `#fff`。

详见 [foundations.md](foundations.md) 第 3 节。

---

## 步骤 4：补状态与交互

**通过条件**：断网、空数据、报错，三个场景页面都有话说。

每个可交互元素 **5 态**：default / hover / active / focus-visible / disabled。
每个数据页 **4 态**：loading / empty / error / success（含无权限、超时）。

- **焦点必须可见**：`outline: 2px solid; outline-offset: 2px`。禁止裸写 `outline: none`。
- **100ms 内要有反馈**（按下态、按钮 loading、骨架屏）；>1s 给进度。
- **破坏性操作**要二次确认或可撤销，文案写清后果。
- **空状态**：一句人话 + 一个明确动作，不要只写"暂无数据"。
- **动效**：桌面 150–200ms、移动 200–300ms；进场减速、退场更快；只动 `transform` / `opacity`；必须响应 `prefers-reduced-motion`。

组件级状态规格见 [components.md](components.md)，交互规则见 [interaction.md](interaction.md)。

---

## 步骤 5：可读性与无障碍

| 项 | 标准 |
|---|---|
| 正文对比 | ≥ 4.5:1 |
| 大字对比（≥18px 或 ≥14px 粗体） | ≥ 3:1 |
| 组件边界 | ≥ 3:1 |
| 触控目标 | ≥ 44×44（WCAG 2.2 AA 底线 24×24） |
| 缩放 | 200% 不破版 |
| 信息传达 | 不只靠颜色（错误 = 色 + 图标 + 文案） |

完整清单见 [interaction.md](interaction.md) 第 7 节。

## 评分卡（10 项，各 1 分）

| # | 维度 | 通过标准 |
|---|---|---|
| 1 | 约束一致 | 间距/字号/圆角全部在刻度上 |
| 2 | 层次可读 | 模糊测试能分出主次；三级文字色分明 |
| 3 | 留白 | 组间 > 组内；内容宽度受限 |
| 4 | 字体 | ≤2 家族；正文 16px 起；行高分区正确 |
| 5 | 色彩 | 灰度成立；60/30/10；暗色非反色 |
| 6 | 深度 | 阴影分级克制；不靠描边硬凑 |
| 7 | 状态完整 | 5 交互态 + 4 流程态齐全 |
| 8 | 动效 | 时长缓动一致；有 reduced-motion |
| 9 | 可用性 | 十原则抽查无硬伤；可撤销、错误可恢复 |
| 10 | 无障碍 | 对比度、焦点、键盘、尺寸达标 |

**低于 8 分不交付；低于 6 分重做结构，不是修细节。**

机器审查是 0–100 分制：`≥80 相当于 8/10`、`60–79 相当于 6–7.9`、`<60 相当于需重做结构`。

给分必须同时给"差在哪 + 具体怎么改"，只给分数没有价值。

## 反"AI 味"清单（默认不要做）

- 紫→蓝渐变当品牌色、全屏 radial glow
- 所有元素居中、每张卡都加阴影、所有块圆角 20px
- emoji 当图标；装饰插画当空状态
- 满页 `#9ca3af` 当正文色
- 每个功能都做成"图标 + 标题 + 描述"三件套卡片
- 无意义的玻璃拟态、发光描边、粒子背景
- 中英混排不加空格、正文行高 1.0、全大写小字
- 用"看起来很科技"替代信息设计

质感来自：克制的颜色、明确的层级、充足的留白、一致的细节。

## 评审报告模板

输出评审结论时按这个结构，不要散着写：

```markdown
## 结论
__/10（机器分 __/100）。可以交付 / 需修 3 处 / 建议重做结构。

## 最痛的 3 个问题
1. [维度] 现状 → 建议值（为什么）
2. …
3. …

## 逐项得分
（10 项评分卡，只列未满分的项，每项一句怎么补）

## 修改顺序
结构：…（先做，会影响后面）
视觉：…
细节：…
```
