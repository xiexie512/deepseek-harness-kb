## 1. 可用性十原则 → 设计动作

不要只背原则，每条都要落到动作。

| # | 原则 | 落到设计上的动作 | 常见违反 |
|---|---|---|---|
| 1 | 系统状态可见 | 每个异步操作给 loading；上传给百分比；保存给"已保存 12:04"；筛选后告诉结果数 | 点了没反应 |
| 2 | 贴近真实世界 | 用用户的话，不用内部黑话（"待发货"而非"状态码 3"） | 界面出现 system / entity / payload |
| 3 | 用户控制与自由 | 弹窗有 Esc 和关闭；破坏性操作可撤销；多步流程能回退；不强制注册才能浏览 | 没有"返回"，退出即丢数据 |
| 4 | 一致性与标准 | 同一动词只表达一件事；按钮位置固定；遵循平台习惯 | "保存/提交/确认"混用 |
| 5 | 预防错误 | 输入就限制格式，不是提交后报错；危险按钮默认不聚焦；删除要说明后果 | 提交后才说"格式错" |
| 6 | 识别优于回忆 | 选项直接可见；最近使用、历史、搜索补全；把上一步的选择带过来 | 让用户记 ID 或路径 |
| 7 | 灵活高效 | 常用路径 1 次点击可达；给快捷键；批量操作；记住上次设置 | 每一步都要重新选 |
| 8 | 美学与极简 | 每屏一个主行动；删掉不产生决策的装饰 | 一屏 5 个 CTA |
| 9 | 帮助识别与恢复错误 | 说清"发生了什么 + 为什么 + 下一步"；保留已填内容 | "操作失败，请重试" |
| 10 | 帮助与文档 | 空状态和首次使用给引导；复杂字段旁给说明 | 关键说明只存在帮助中心 |

**最常被忽略的三条**：3（没有撤销）、5（提交后才报错）、9（错误文案写成"操作失败"）。

## 2. 状态机

每个界面要有 9 种状态，不能只做"正常路径"。

| 状态 | 要做的设计 | 常见错误 |
|---|---|---|
| 空白（无数据） | 一句人话 + 一个明确动作 | 只写"暂无数据" |
| 首次使用 | 引导而非空白，2–3 步拿到第一个结果 | 直接给空白页 |
| 加载中 | <300ms 不显示；300ms–1s 骨架屏；>1s 进度 | 整页白屏转圈 |
| 部分加载 | 先显示已有内容，局部占位 | 全部等齐才渲染 |
| 错误 | 原因 + 重试 + 备用路径 | 只弹"失败" |
| 无权限 | 需要什么权限、谁能给、怎么申请 | 直接 403 白页 |
| 离线 | 顶部条提示 + 可继续的操作范围 | 静默失败 |
| 成功 | 轻量确认（Toast / 行内变化） | 每次都弹窗庆祝 |
| 超时 / 冲突 | 说明数据可能已变更，给"刷新查看" | 静默覆盖 |

**检查方法**：DevTools 断网、清空数据、返回 500，各看一遍。三遍都过得去才算做完。

## 3. 反馈与等待

| 时长 | 感知 | 处理 |
|---|---|---|
| 0–100ms | 瞬时 | 只需按下态（`scale(.98)` 或颜色加深） |
| 100ms–1s | 可感知但可忍 | 按钮 loading、局部骨架 |
| 1–10s | 注意力会飘 | 进度条 / 分步文案 / 允许后台继续 |
| > 10s | 会离开 | 转异步任务 + 完成通知 |

### 规则

- **100ms 内必须有一次视觉变化**，否则用户重复点击。
- 防重复提交用 loading 态，不是直接 disabled 灰掉——灰掉没有"我收到了"的反馈。
- **乐观更新**：点赞、收藏、勾选用先改 UI 再发请求，失败回滚并提示。
- Toast 停留 3–5s，可关闭，不遮挡主操作；同时最多 1–2 条。
- 不用假进度条（走到 90% 卡住）。不确定进度用不确定态（往复条）。
- 长任务给"可以离开"的承诺："完成后会通知你"。

## 4. 动效规范

| 场景 | 时长 | 曲线 |
|---|---|---|
| 按下 / hover | 100–150ms | `ease-out` |
| 小元素出现、Tooltip | 150–200ms | `cubic-bezier(.2,0,0,1)` |
| 面板展开、抽屉 | 200–300ms | `cubic-bezier(.2,0,0,1)` |
| 页面转场、共享元素 | 300–500ms | `cubic-bezier(.2,0,0,1)`（减速） |
| 退场 | 进场的 60–80% | `cubic-bezier(.4,0,1,1)`（加速） |

参考 Material 3：强调型 500ms（同屏进出）、进场 400ms、退场 200ms、标准 300ms。

### 规则

- 只动 `transform` 和 `opacity`。动 `width` / `height` / `top` / `left` 会重排掉帧。
- **进场减速、退场加速**。反了会觉得"黏"。
- 动效要有因果：列表项从点击位置展开，不要从屏幕中心缩放。
- 一个界面只用一套时长体系（150 / 200 / 300）。
- 高频交互（滚动、输入、hover 列表）不加动画。
- 必须尊重系统设置：

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: .01ms !important;
    transition-duration: .01ms !important;
    scroll-behavior: auto !important;
  }
}
```

### 什么时候不该动

- 用户正在等待的操作（等待时动画会显得更慢）。
- 表单输入与校验反馈（延迟会打断节奏）。
- 数据表格排序（位移会让用户丢失当前行位置）。

## 5. 微交互清单

这些细节决定"顺不顺手"，逐项确认：

| 交互 | 应有反馈 |
|---|---|
| 复制 | 图标变对勾 1.5s + "已复制" |
| 收藏 / 点赞 | 立即变色 + 轻微 scale，失败回滚 |
| 删除 | 行淡出 + 撤销 Toast（5s） |
| 上传 | 缩略图立即出现 + 进度条 |
| 拖拽 | 落下位置高亮 + 阴影提升 |
| 展开 / 收起 | 箭头旋转 180°，内容 200ms |
| 输入焦点 | 描边变品牌色 + 2px 外环 |
| 滚动到底 | 不再有"加载更多"按钮的死循环 |
| 空输入提交 | 聚焦第一个字段，不弹全局错误 |
| 长按 | 触觉反馈（移动端），并有可见替代入口 |

## 6. 表单与错误

- 标签在上方，不用 placeholder 当标签（输入后标签就消失）。
- 必填 `*` + 可选写"（选填）"。
- 输入类型要对：`email` / `tel` / `number` / `url`。
- **失焦校验**，不要每敲一字报错；错误在字段下方。
- 错误文案公式：`发生了什么 + 为什么 + 怎么修`。
  - 差："邮箱格式错误"
  - 好："邮箱需要包含 @，例如 name@example.com"
- 提交失败保留输入，聚焦第一个错误字段。
- 长表单分组（3–7 字段一组），给进度。
- 按钮文案写结果："保存并发布""发送邀请"。

### 错误文案三级

| 级别 | 用在哪 | 例 |
|---|---|---|
| 字段级 | 单个字段格式问题 | "手机号需要 11 位数字" |
| 表单级 | 多个字段或提交失败 | "有 3 个字段需要修改，已定位到第一个" |
| 系统级 | 服务不可用 | "服务暂时不可用，已自动重试，也可稍后再试" |

## 7. 导航与信息架构

- 顶层导航 ≤ 7 项，超过就分组或降级。
- 层级 ≤ 3 层。第 4 层开始用户会迷路。
- 当前位置可见：面包屑 / 选中态 / 页面标题。
- **渐进披露**：先给 80% 场景需要的信息，高级选项收进"更多设置"。
- 搜索是逃生通道：内容 > 30 项必须有搜索或筛选。
- 筛选项 > 5 个收进面板，不要平铺一排。
- 返回行为可预测：浏览器返回、手势返回、面包屑结果一致。

## 8. 键盘与快捷操作

| 键 | 应有行为 |
|---|---|
| Tab | 按阅读顺序移动焦点 |
| Shift+Tab | 反向 |
| Enter | 激活链接/按钮 |
| Space | 激活按钮、切换勾选 |
| ↑↓ / ←→ | 在 Tab、菜单、单选组内移动 |
| Esc | 关闭弹窗/下拉/取消当前操作 |

- 不用正 `tabindex`（> 0），会打乱顺序。
- 弹窗内焦点锁定，关闭后回到触发元素。
- 常用操作给快捷键（保存 Cmd+S、搜索 Cmd+K），并在菜单里标注。
- 快捷键不能与输入法冲突（避免单字母全局快捷键）。

## 9. WCAG 2.2 AA 检查清单

### 可感知

- [ ] 所有图片有 `alt`；装饰图 `alt=""`
- [ ] 正文对比 ≥ 4.5:1；大字（≥18px 或 ≥14px 粗体）≥ 3:1
- [ ] 组件边界、图标、图表色块 ≥ 3:1
- [ ] 不只用颜色传达信息（红框 + 图标 + 文案）
- [ ] 200% 缩放不出现横向滚动、不截断文字

### 可操作

- [ ] 全部功能键盘可达，Tab 顺序符合阅读顺序
- [ ] 焦点可见：`outline: 2px solid; outline-offset: 2px`
- [ ] 不用 `outline: none` 且无替代
- [ ] 触控目标 ≥ 24×24 CSS px（AA 底线），移动端 44×44
- [ ] 弹窗焦点锁定，Esc 可关闭，关闭后焦点回到触发元素

### 可理解

- [ ] `<html lang="zh-CN">`
- [ ] 每页只有一个 `h1`，标题层级不跳级
- [ ] 链接文字有意义，不写"点击这里"
- [ ] 表单有显式 `<label for>`，错误有 `aria-describedby`

### 健壮

- [ ] 语义标签（`button` / `nav` / `main`），不用 div 假装按钮
- [ ] ARIA 状态正确（`aria-expanded` / `aria-selected` / `aria-live`）
- [ ] 动态提示用 `aria-live="polite"`

**自动化工具只能查约 30%**，必须手动：拔掉鼠标只用键盘走一遍，开系统朗读器听一遍。

## 10. 移动端手势与安全区

- 点击区 ≥ 44×44；视觉可小，用 padding 或伪元素扩大热区。
- 底部避开 Home Indicator：`padding-bottom: env(safe-area-inset-bottom)`。
- 顶部避开刘海：`padding-top: env(safe-area-inset-top)`。
- 主操作放下 1/3 屏，拇指可达。
- 手势冲突：页面横滑与抽屉横滑不要抢；滑动删除必须有按钮替代。
- 长按 = 更多操作，但必须同时有可见入口。
- 键盘弹出时输入框滚到可见区，不被遮挡。
- 下拉刷新与横向滑动不要同时存在（会互相误触）。

## 11. 欺骗性设计黑名单（伦理硬门）

这一节不参与评分：**命中任意一条，直接判不交付**。AI 生成界面时最容易顺手带上这些模式，因为它们在高转化模板里出现频率很高。

### 黑名单

| 模式 | 表现 | 为什么是硬门 |
|---|---|---|
| **确认羞辱**（confirm shaming） | 拒绝按钮写"不，我不想省钱 / 我更喜欢多花钱" | 用羞耻感绑架选择，用户是被设计逼着点的 |
| **误标动作** | "开始我的免费试用" 实际是订阅；"继续" 实际是付款 | 动作与结果不符，等同诱导 |
| **隐藏成本** | 价格页只展示月费，税费/最低消费/自动续费在提交后才出现 | 关键决策信息后置 |
| **暗默认**（预勾选） | 营销邮件、附加保险、自动续费默认勾上 | 默认项应当是最保守的那个 |
| **视觉降级拒绝项** | "取消"做成 12px 灰字，或藏在折叠区 | 选项必须同等可见、同等可点 |
| **强制挽留** | 注销 / 退订要走 5 步、要打电话、要人工审核 | 退出路径必须和进入路径一样短 |
| **虚假紧迫** | "仅剩 2 件""3 人正在看" 但数据是假的或恒定 | 制造不存在的时间压力 |
| **无法关闭的打扰** | 弹窗没有关闭按钮，或关闭按钮 8px | 关闭能力是底线 |
| **假装系统消息** | 用系统通知样式伪装广告 | 借用信任来源 |

### 自检三问

1. **把这段文案念给用户听，他会觉得被尊重还是被套路？**
2. **如果用户逐字读完所有文字，还会做出同样的选择吗？** 会 → 通过；不会 → 就是靠"没读到"在转化。
3. **拒绝/退出/取消，是不是和接受一样容易？** 不是 → 改。

### 允许的边界

紧迫感、社会认同、优惠提示本身不违规，前提是**真实且可验证**：真实库存、真实截止时间、真实评价数。写不出真实数据就不要用这个手段。

## 体验故障 → 处方

| 现象 | 多半是 | 处方 |
|---|---|---|
| 用户重复点击 | 100ms 无反馈 | 加按下态 + loading |
| 用户不敢点 | 后果不明 | 按钮文案写结果，危险操作加说明 |
| 用户填错一堆 | 提交后才校验 | 失焦即时校验 + 格式约束 |
| 用户迷路 | 层级过深 / 无当前位置 | 面包屑 + 选中态 + 层级压到 3 层 |
| 用户反复确认"存了吗" | 无保存反馈 | 自动保存 + "已保存 14:32" |
| 用户误删 | 无撤销 | 5 秒撤销 Toast + 二次确认 |
| 用户看完不知道下一步 | 空状态无引导 | 空状态给一个主操作 |
