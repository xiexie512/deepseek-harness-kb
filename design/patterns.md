# 页面模式

组件解决"零件"，页面模式解决"装配"。同一类页面用同一套骨架，用户第二次进来就知道东西在哪。

## 1. 列表页

**目的**：让用户在 3 秒内判断"有没有我要的"，并能立刻动手。

### 骨架（自上而下）

```
页面标题区   [标题 30–36]        [主操作按钮]
说明 / 计数  [一句说明 · 共 128 条]
筛选区       [搜索框] [筛选 2–4] [排序] [视图切换]
内容区       [表格 / 卡片网格 / 列表]
分页 / 批量条 [已选 3 项] [批量操作]
```

### 数值

| 项 | 值 |
|---|---|
| 页面左右边距 | 24–32（桌面） |
| 标题区下间距 | 16–24 |
| 筛选区下间距 | 16 |
| 表格与分页间距 | 16–24 |
| 首屏可见条目 | 8–12 条（不要一屏只有 4 条） |

### 规则

- **默认给一个排序**（最近更新/最相关），不要默认无序。
- 计数放在标题旁，让人知道规模（"共 128 条"）。
- 筛选条件以 chips 形式回显，可单个移除，可"清空全部"。
- 列表为空时区分三种原因（见第 6 节）。
- 操作入口：行内最多 3 个，其余进"更多"；整行点击进入详情。
- 分页优先于无限滚动（后台/管理端）；信息流类才用滚动加载。
- 批量选择后，操作条吸顶或吸底，不要挡住内容。

### 反例

- 筛选器是一排彩色胶囊按钮，分不清哪个已选。
- 标题区没有主操作，用户找不到"新建"。
- 每行都放 6 个文字操作，挤成一片。
- 空列表只显示"暂无数据"。

## 2. 表单页

**目的**：让用户一次填对，失败时知道改哪。

### 骨架

```
标题 + 一句说明（这表单一共几步 / 要准备什么）
分组 1  [小标题]  →  3–7 个字段
分组 2  [小标题]  →  3–7 个字段
操作区  [取消] [保存并发布]（右下或底部固定）
```

### 数值

| 项 | 值 |
|---|---|
| 表单容器宽 | 480–640（单列），不超过 720 |
| 字段垂直间距 | 16–20 |
| 分组间距 | 32–48 |
| 标签与输入框 | 4–8 |
| 输入框高度 | 40（桌面）/ 48（移动端） |
| 两列并排 | 仅在字段天然成对时（起止日期、省市） |

### 规则

- **单列优先。** 两列会打乱阅读顺序，除非字段成对。
- 标签在上方；占位符只放示例（"如：name@example.com"）。
- 必填用 `*`，可选字段写"（选填）"。
- 长表单（> 12 字段）分组，每组有标题；需要时给步骤。
- 破坏性/离开：未保存时离开要提示，且保留草稿。
- 提交按钮：主按钮在右，次要（取消）在左；移动端主按钮撑满底部。
- 提交中：按钮 loading + 禁止重复点击；失败时保留输入并聚焦第一个错误。

### 反例

- 14 个字段一屏排完，没有分组。
- 全部字段两列，用户在左右之间跳。
- 校验只在提交时，且只标"格式错误"。
- 主按钮写"提交"。

## 3. 详情页

**目的**：先给结论，再给依据，最后给操作。

### 骨架

```
面包屑（层级 ≥ 3 时）
标题区       [标题 30–36] [状态标签]     [主操作] [更多]
关键信息区   3–6 个字段（两列），或 KPI 行
主内容       描述 / 图片 / 图表 / 关联列表
副栏（可选）  相关信息、历史、联系人——固定宽度 280–320
```

### 数值

| 项 | 值 |
|---|---|
| 主栏 / 副栏比例 | 2/3 + 1/3，或主栏 720 + 副栏 320 |
| 关键字段间距 | 16–24 |
| 字段标签 | 12–13 / 弱色；值 14–16 / 主色 |
| 区块间距 | 32–48 |

### 规则

- 状态标签放标题同一行，一眼看到当前状态。
- 关键信息用"标签 + 值"两列网格，不要一句话里塞三个字段。
- 长文本先给摘要（2–3 行），可展开全文。
- 时间线/历史按时间倒序，最近的在最上。
- 空关联（没有评论、没有附件）用轻量空状态，不要占太大面积。

### 反例

- 标题下面立刻一大段描述，用户找不到状态和操作。
- 十个字段平铺成一列，标签和值混在一起读不清。
- 主操作在页面最底部，要滚三屏才看到。

## 4. 设置页

**目的**：可预期、可恢复、不误伤。

### 骨架

```
左侧分类导航（200–240，5–8 项）   右侧内容（单列，≤ 720）
每项：标题 + 一句说明 + 控件（右侧对齐）
保存方式：自动保存（显示"已保存 14:32"）或底部固定保存条
```

### 规则

- 一类设置一屏，不要把所有开关堆一页。
- 开关类**立即生效**并给轻提示；表单类需显式保存。两者不要混。
- 危险设置（删除账号、清空数据）单独分组，放在最下，视觉上分离。
- 变更后可撤销（至少 5 秒内）。
- 说明文字解释"会影响什么"，不要只有开关名。

### 反例

- 20 个开关一页，无分组。
- 改了自动生效的设置却显示"保存"按钮（用户不知道到底存没存）。
- 删除按钮和其他设置并排，一样的大小和颜色。

## 5. 搜索与筛选

### 搜索框

| 项 | 值 |
|---|---|
| 高度 | 36–40（工具条内）/ 44（页面主搜索） |
| 图标 | 左侧，16–20 |
| 清除按钮 | 有输入时出现 |
| 结果反馈 | 输入后 300ms 防抖触发 |

- 有搜索就必须有"无结果"状态，并给替代建议（换个关键词、清空筛选）。
- 搜索历史/联想最多 5–8 条。
- 搜索结果高亮关键词，但不要整段染色。

### 筛选

- 常用筛选 ≤ 4 个直接露出，其余收进"更多筛选"。
- 已选条件必须回显（chips 或按钮上的计数）。
- 应用筛选后显示结果数量，并提供"清空"。
- 筛选面板里的"应用/重置"固定在底部，不要滚出视野。

### 排序

- 3–5 个选项，默认选中一个并显示当前排序。
- 用下拉而不是一排按钮（按钮会误以为是筛选）。

## 6. 空状态体系

三种空，三套话术——这是最容易被合并掉的地方。

| 类型 | 触发 | 内容 | 主操作 |
|---|---|---|---|
| 首次为空 | 数据真的没有 | "还没有项目，创建第一个" + 一句价值说明 | 创建 |
| 筛选为空 | 有数据但条件太严 | "没有符合条件的结果" + 当前条件 | 清空筛选 |
| 无权限 | 有数据但看不了 | "需要管理员权限才能查看" | 申请权限 / 联系管理员 |
| 出错 | 请求失败 | "加载失败，可能是网络问题" | 重试 |

### 规则

- 空状态占满内容区高度（至少 240px），不要缩成一行字。
- 插图可选，但要与产品风格一致；没有插图时靠排版和留白撑住。
- 文案用产品自己的语言，不用"暂无数据"这种系统话。
- 空状态不放广告或不相关推荐。

## 7. 引导与首次使用

### 三种引导，选一种，不要叠加

| 方式 | 适用 | 成本 |
|---|---|---|
| 空状态引导 | 功能有明确的第一个动作 | 低，推荐 |
| 内联提示（tooltip / 高亮） | 界面上有不 obvious 的入口 | 中 |
| 分步向导 | 流程复杂且必须按顺序 | 高，谨慎 |

### 规则

- **2–3 步内让人拿到第一个结果。** 引导的目的不是介绍功能，是让人完成一次成功操作。
- 可跳过，且跳过之后不再重复弹。
- 不使用全屏遮罩式多页引导（用户会直接关掉）。
- 进度可见（"1/3"），可随时退出且不丢数据。
- 引导文案用第二人称 + 动作："选择一个模板开始"。

### 反例

- 首次进入连弹 5 个提示气泡。
- 引导页介绍 8 个功能，一个都没用上。
- 关掉后下次登录又弹。

## 8. 登录与注册

### 骨架

- 单列窄容器（360–420），垂直居中偏上（不是正中）。
- 标题 + 一句说明 + 表单（2–4 个字段）+ 主按钮 + 次要方式 + 法务文案。
- 第三方登录放在主表单下方，用分割线"或"隔开。

### 规则

- 字段越少越好：邮箱/手机 + 密码即可；其它信息后置。
- 密码错误文案统一（不区分"用户不存在"和"密码错"），避免泄露账号是否存在。
- 主按钮文案明确："登录""创建账号"，不写"继续"。
- 验证码/二次验证要说明为什么需要，并给"收不到？"的出口。
- 法务条款放在按钮下方，11–12px，但对比度仍需 ≥ 4.5:1。
- 记住登录状态默认开启（可取消）。

### 反例

- 登录页放巨大的品牌插画占半屏，表单被挤到角落。
- 注册要填 9 个字段。
- 错误只提示"登录失败"。

## 9. 多步骤流程

| 项 | 规则 |
|---|---|
| 步数 | 2–5 步；超过 5 步合并或改为单页分区 |
| 步骤指示 | 顶部步骤条 + "第 2 步 / 共 4 步" |
| 导航 | 上一步 / 下一步；最后一步是明确的动作（"发布"） |
| 数据 | 每步完成即保存草稿，可退出再回来 |
| 校验 | 每步只校验本步字段，不要一次性报全表单错误 |
| 回退 | 允许回退修改，且不丢已填内容 |

**原则**：宁可 3 步清楚，不要 6 步显专业。步骤越多，流失越高。
