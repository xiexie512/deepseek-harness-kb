## 1. 网页 / 落地页

### 结构顺序（自上而下）

1. **导航**：Logo + 4–6 个入口 + 1 个主 CTA。高度 64–72px；吸顶时半透明底 + 1px 下边线。
2. **Hero**：一句主张（≤12 字）+ 一句支撑（≤30 字）+ 1 主按钮 + 1 次级链接。
3. **证据**：客户 Logo 墙 / 数据 / 评价，三选二，不要全堆。
4. **功能**：3 个，不要 6 个。标题写"结果"，不是"功能名"。
5. **深入**：真实截图或演示，不要占位框。
6. **CTA 收尾**：重复主 CTA，降低决策成本（"免费开始，无需信用卡"）。
7. **页脚**：分组链接 + 法务信息。

### 数值

| 项 | 值 |
|---|---|
| 内容容器 | 1080–1280px |
| Hero 上下留白 | 96–128px |
| 区块间距 | 64–96px |
| 标题层级 | 48 / 30 / 20 / 16 |
| 主按钮 | 高 44–48，左右内边距 20–24，圆角 8 |
| 正文宽度 | 65ch |
| 卡片网格 | 3 列，gap 24，`minmax(280px, 1fr)` |

### 常见错误

- Hero 里三个同等权重的按钮 → 不知道点哪个。
- 六个等宽功能卡 → 像模板，没有重点。
- 全站 14px → 没有节奏。
- 标题居中、正文居中、按钮居中 → 三连居中。
- 每块换一种背景色 → 页面碎成拼贴。

### 提升质感的小动作

- 首屏放真实产品截图，带一点阴影和圆角，比插画可信。
- 数字用等宽字体并带单位（"3.2 秒"不是"3.2"）。
- 卡片 hover 只做 `translateY(-2px)` + 阴影升一级，200ms。
- 用一条细分隔线（`1px rgba(15,23,42,.06)`）代替整块背景色分区。

## 2. App / 移动端

### 结构

- 导航：底部 Tab 3–5 个，或顶部大标题 + 返回。不要两者叠加。
- 首屏：状态栏 → 大标题 → 内容。标题 28–34px / 700。
- 列表项高 56–72，左图标 24、右箭头 16，分隔线只左边缩进。
- 详情页：主图 + 标题 + 元信息 + 主操作固定底部。

### 数值

| 项 | 值 |
|---|---|
| 页面左右边距 | 16（紧凑列表）/ 20（内容页） |
| 卡片圆角 | 12–16 |
| 主按钮 | 高 48–52，圆角 12，宽 = 屏宽 − 32 |
| 正文 | 16px / 行高 26 |
| Tab 图标 | 24，标签 11–12 |
| 触控区 | ≥ 44×44 |
| 安全区 | 顶部 `env(safe-area-inset-top)`，底部 `env(safe-area-inset-bottom)` |

### 规则

- 主操作放下 1/3 屏，拇指可达。
- 键盘弹出时输入框上移，不被遮挡。
- 手势必须有可见替代（滑动删除也要有删除按钮）。
- 单屏信息密度低于桌面：一屏一个主任务。

### 常见错误

- 顶部同时有返回、标题、搜索、更多、头像 → 五个元素抢注意力。
- 列表项都做成大卡片 + 大圆角 + 阴影 → 满屏气泡感。
- 底部导航 6 个 Tab → 每个都点不准。

## 3. 后台 / 仪表盘

后台的美感来自**秩序**，不是装饰。密度高但要对齐。

### 结构

1. 左侧导航（200–240，可折叠）+ 顶栏（面包屑 / 搜索 / 用户）。
2. 页面标题区：标题 + 一句说明 + 右侧主操作。
3. KPI 行：3–5 个指标卡，数字最大，单位和对比最小。
4. 筛选区：搜索 + 2–4 个下拉 + "更多筛选"。
5. 主内容：表格或图表，占 60% 以上屏高。
6. 分页 / 批量操作条（选中后浮现）。

### 数值

| 项 | 值 |
|---|---|
| 表格行高 | 48 标准 / 40 紧凑 |
| 表头 | 12–13 / 500 / 次级色 |
| 单元格内边距 | 左右 12–16，上下 8–12 |
| 数字列 | 右对齐 + `tabular-nums` |
| KPI 数字 | 32–40 / 600 |
| 卡片内边距 | 20–24 |
| 模块间距 | 16–24 |

### 规则

- **对齐优先于美观**：表头、内容、筛选器左边缘必须对齐。
- 状态用**标签**（底浅、字深、圆角 4），不要用彩色文字。
- 表格超过 8 列：固定前 2 列 + 横向滚动。
- 数字右对齐、文字左对齐、日期全站统一。
- 图表与表格不要重复表达同一份数据。
- 空状态、骨架、错误页三件套必做。

### 常见错误

- 每个 KPI 都配大图标 + 渐变底 → 像营销页。
- 斑马纹 + 全边框 + 竖线 → 三重分隔。
- 筛选器一排彩色胶囊 → 分不清已选。
- 图表 8 种颜色 → 无法对应。

## 4. PPT / 幻灯片

**一页一个论点。标题写结论，不写主题**（"成本下降 18%"而不是"成本分析"）。

### 数值（16:9，13.333 × 7.5 in）

| 项 | 值 |
|---|---|
| 页边距 | 上下 0.6–0.8 in，左右 0.8 in |
| 页标题 | 32–40pt / 700 |
| 正文 | 18–20pt（最小 16pt，后排要看得见） |
| 说明 / 来源 | 12–14pt，次级色 |
| 行距 | 1.15–1.3（演示比文档紧） |
| 每页文字 | ≤ 60 字，超过就拆页 |
| 每页要点 | 3 条，最多 4 条 |
| 配色 | ≤ 3 色（主 + 中性 + 强调） |
| 字体 | ≤ 2 家族 |

### 页面模板

| 页型 | 构成 | 留白 |
|---|---|---|
| 封面 | 主标题 + 副标题 + 日期/讲者 | 40–50% |
| 目录 | 4–6 项，编号用大号数字做锚点 | 30% |
| 过渡 | 一个大号数字/词 + 一句主张 | 70% |
| 内容 | 标题左上，内容占 2/3，来源右下 | 25–30% |
| 数据 | 结论先行 + 一张图（去图例与网格线）+ 一句注解 | 25% |
| 结尾 | 行动项 / 联系方式，不只是"谢谢" | 50% |

### 规则

- 标题位置全篇一致（固定坐标），不要每页飘。
- 图片撑满一侧或出血，不要小图居中漂浮。
- 项目符号不超过两级，超过就改结构。
- 数字放大、加粗、给对比（"↑ 18%"）。
- 母版里定好标题/正文/注释三种文本框。

### 常见错误

- 一页 6 个要点 + 复杂图 + 一段备注。
- 每页不同装饰色块和图标。
- 正文 14pt 以下。
- 全篇居中 + 宋体。

## 5. 报告 / 文档排版

### 数值（A4，中文）

| 项 | 值 |
|---|---|
| 页边距 | 上下 2.54cm，左右 2.2–3.18cm |
| 正文 | 小四 12pt（或五号 10.5pt），行距 1.5 倍 |
| 一级标题 | 三号 16pt / 加粗 / 段前 24pt 段后 12pt |
| 二级标题 | 四号 14pt / 加粗 / 段前 18pt 段后 6pt |
| 三级标题 | 小四 12pt / 加粗 |
| 图表标题 | 五号 10.5pt，居中；图下表上 |
| 表格文字 | 五号 10.5pt，行高 1.2 |
| 行宽 | 每行 30–40 中文字 |

### 结构

1. 标题页：标题 + 副标题 + 单位 + 日期。
2. 摘要（可选）：3–5 句，说清结论。
3. 目录：超过 5 页必须有。
4. 正文：每章开头一段导语。
5. 结论 / 建议。
6. 附录、参考。

### 规则

- 标题层级 ≤ 4 级，编号统一（`1` / `1.1` / `1.1.1`）。
- **段首缩进 2 字符 或 段间距区分，二选一**，不要同时用。
- 正文两端对齐（中文），数字/英文可左对齐，全篇统一。
- 图表必须有编号和标题（"图 1 2025 年季度营收"）。
- 页眉放文档名，页脚放页码；封面与目录不显示页码。
- 强调用加粗，不用彩色字或下划线（正式文档里彩色字像批注）。

### 常见错误

- 全文一个字号，靠段间距硬撑层级。
- 表格 10 列且全部居中。
- 图表截图尺寸不统一。

## 6. 海报 / 封面 / 主视觉

### 信息层级（只允许 4 层）

1. 主标题（占视觉面积 25–40%）
2. 副标题 / 一句话说明
3. 关键信息（时间、地点、价格、二维码）
4. Logo / 主办方 / 免责

### 构图

- 一个视觉焦点，其余全部退后。焦点占画面 1/3，用三分法或黄金分割。
- 大标题压图（出血）比放在安全区内更有张力。
- 留白 ≥ 30%，不要四边贴满。
- 文字与背景对比 ≥ 4.5:1；压图加渐变蒙版 `linear-gradient(to top, rgba(0,0,0,.7), transparent)`。
- 二维码 ≥ 2.5cm × 2.5cm，四周留白 ≥ 0.5cm，不压在复杂纹理上。

### 字体

- 主标题用一个有性格的字体（黑体加粗 / 衬线 / 手写），副标题用中性字体，形成对比。
- 主标题字号是副标题的 **2.5–4 倍**，差不够就"平"。
- 标题字距收紧（-0.02em），英文标签字距拉开（+0.08em）。
- 深底浅字或浅底深字；不要中间调对中间调（灰底灰字）。

### 配色

- 主色 1 + 中性 1 + 点缀 1，三色足够。
- 大面积渐变慎用，容易廉价；单色 + 一点高光更稳。

### 常见错误

- 五个信息块一样大 → 没有主次。
- 全页居中 → 像通知，不像海报。
- 6 种字体/字号。
- 主标题用手写体导致难读。

## 7. 数据图表

### 选型

| 目的 | 图型 | 说明 |
|---|---|---|
| 比大小（类别少） | 条形图（横向） | 标签好读，中文尤其 |
| 看趋势 | 折线图 | 时间序列 |
| 看构成（≤5 类） | 堆叠条 / 环形图 | 超过 5 类改表格 |
| 看分布 | 直方图 / 箱线图 | |
| 看相关 | 散点图 | 加趋势线要谨慎 |
| 单一值进度 | 进度条 / 大数字 + 对比 | 最有效 |
| 看流程/层级 | 桑基图 / 树图 | 学习成本高，慎用 |

### 规则

- **一图一结论**。标题写结论（"Q3 转化率提升 12%"），不写"转化率趋势图"。
- 去掉：多余网格线、背景色块、3D、阴影、渐变填充、边框。
- 只留必要轴线：横向基线 + 4–6 个刻度。
- **直接标注**关键点，不要让用户查图例。
- 分类色 ≤ 5；超过就分组或改图型。
- 强调用一色，其余中性灰（"高亮一条线，其他变灰"）。
- 同页所有图表用同一套配色和字号。
- 数字：千分位、统一小数位、单位放轴标题。
- 柱状图从 0 开始；折线图可不从 0 开始但要说明。

### ECharts / Chart.js 起手配置

```js
grid: { left: 8, right: 8, top: 24, bottom: 8 },
axisLine: { lineStyle: { color: 'rgba(15,23,42,.15)' } },
splitLine: { lineStyle: { type: 'dashed', color: 'rgba(15,23,42,.08)' } },
tooltip: { trigger: 'axis' }
```

### 常见错误

- 饼图分 8 类。
- 双 Y 轴硬凑两个量级。
- 12 条线用 12 种颜色。
- 3D 饼图 + 阴影 + 渐变。

## 8. Markdown 文档与仓库 README

文档也是设计产物。同一仓库的文档排版一致，读起来才不像草稿堆。

### 骨架

```
# 一级标题（只出现一次）
> 一句话说明这段是什么、给谁看、读完能得到什么

## 目录（超过 5 个章节时加）

## 章节
### 小节

## 相关文档
- [xx](xx.md)：一句话
```

### 规则

| 项 | 规范 |
|---|---|
| 标题层级 | 不跳级；`#` 只用一个 |
| 段落长度 | 3–6 行；超过就拆 |
| 列表 | 同类信息用列表，不要写成一大段顿号句 |
| 表格 | 三列以内最好；列多时把次要列合并成一行说明 |
| 代码块 | 必须标语言；命令不加 `$` 前缀，方便复制 |
| 链接 | 用相对路径（`../docs/x.md`），仓库内跳转不依赖网络 |
| 强调 | 加粗用于关键结论，全篇不要超过每节 3 处 |
| 图示 | 用表格或代码块表达结构，不要用图片代替可复制文本 |
| 中英混排 | 中英文之间加空格 |
| 长度 | 单文件 100–300 行；超过就拆文件并在索引里登记 |

### 索引文件（llms.txt / README）要点

- 每条一行：`- [名称](链接): 一句话说清内容与适用场景`。
- 按用途分组（官方文档 / 项目 / 笔记 / 设计规范），不要按时间堆。
- 末尾给"快速导航"：想做什么 → 读哪篇。
- 说明网络回退方式（raw 不可达时用 jsDelivr）。

### 常见错误

- 一个文件 800 行，目录缺失。
- 所有章节都是 `##`，没有层级。
- 图片代替表格，模型抓不到内容。
- 链接用绝对 GitHub 地址，本地打开就跳外链。
