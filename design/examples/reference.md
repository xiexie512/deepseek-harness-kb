# 参考方案清单

抄要抄对地方：**抄结构与决策，不抄视觉皮肤**。下面每个都能直接打开看，都标了"借什么 / 别借什么"。

## 一、设计系统（拿数值与组件规格）

| 方案 | 链接 | 借什么 | 别借什么 |
|---|---|---|---|
| **Apple HIG** | developer.apple.com/design/human-interface-guidelines | 触控尺寸（44pt）、安全区、层级由"内容-控件-导航"三层决定、系统态文案 | 大量毛玻璃与动效，Web 上性能代价高 |
| **Material 3** | m3.material.io | 动效时长（500/400/300/200ms）、状态层级、token 化的色彩角色 | 强品牌色大面积铺（Web 后台会显得吵） |
| **Ant Design** | ant.design | 后台组件规格（表格 48 行高、表单 3 列栅格）、中文字号（14 正文） | 默认蓝 + 大量边框，容易"一眼 Ant" |
| **Arco Design** | arco.design | 中后台密度档位、暗色主题映射 | 组件阴影偏重 |
| **shadcn/ui** | ui.shadcn.com | 中性色阶做法、组件无重阴影、`radius` 单变量控制全站 | 直接搬配色（偏灰，品牌感弱） |
| **Radix Primitives** | radix-ui.com | 无障碍行为（焦点管理、Esc、aria 属性） | 视觉层几乎为零，需自己补 |
| **IBM Carbon** | carbondesignsystem.com | 数据密集型界面的排版与表格规范、10px 间距体系 | 字重偏细，中文会显虚 |
| **GitHub Primer** | primer.style | 代码/文档场景的排版、行内代码与表格样式 | 高密度配色，营销页不合适 |
| **Tailwind UI** | tailwindui.com | 落地页区块顺序、留白节奏 | 直接照抄会出现"千篇一律的紫色渐变" |

## 二、产品（拿"感觉"与具体做法）

| 产品 | 借什么 | 别借什么 |
|---|---|---|
| **Linear** | 极窄边线 + 极浅灰阶 + 单一强调色；列表行高 40；信息密度高但不挤 | 深色为主，浅色版要自己调 |
| **Vercel / Geist** | 大字标题 + 紧字距（-0.02em）；黑底白字对比结构 | 纯黑大块面积，长文阅读疲劳 |
| **Stripe** | 表单错误文案的具体程度；文档页的三栏结构 | 大量动效与插图 |
| **Notion** | 文档排版的层级（标题-正文-引用-代码块）不用颜色也能分层 | 侧栏交互复杂度 |
| **Figma** | 组件状态矩阵的画法（用于评审，不用于产品界面） | 密集工具栏 |
| **Airbnb** | 卡片圆角 12 + 单层阴影 + 图片占比；移动端底部固定主操作 | 大图依赖，无图场景失效 |

## 三、方法论（拿判断标准）

- **Nielsen 十原则**（nngroup.com）——评审时逐条打勾，见 [../interaction.md](../interaction.md) 第 1 节。
- **WCAG 2.2 快速参考**（www.w3.org/WAI/WCAG22/quickref/）——AA 的硬门槛，见 [../interaction.md](../interaction.md) 第 9 节。
- **Refactoring UI**（refactoringui.com）——"约束刻度"的原始出处：间距、字阶、灰度都先定刻度再取值。
- **Laws of UX**（lawsofux.com）——解释"为什么这样感觉更好"，适合在评审里说服人。

## 四、怎么用这张清单

1. **先定血缘**：一个项目只选 1 个设计系统做骨架（后台选 Ant/Arco，营销页选 Tailwind UI 的区块顺序），不要混三套。
2. **只借三层**：间距刻度、字号字阶、组件尺寸。配色与圆角统一按 [../foundations.md](../foundations.md) 自己定。
3. **对照检查**：拿目标产品的截图和自己的并排放大到 20%，看层次是否一致；不一致时先调层级，别急着换颜色。
4. **别抄皮肤**：抄"卡片圆角 12 + 阴影两级"，不要抄"某个具体渐变"。皮肤会过时，结构不会。
